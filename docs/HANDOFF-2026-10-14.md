## 接续顺序与验证

1. 拉取包含本交接文档的代码快照，恢复上述被忽略素材，核对90条对白的音频存在性和v3哈希。
2. 安装Node.js ≥22.13及项目依赖；根目录和三个app各自按lockfile安装。先执行`npm run skills:check`、`npm run validate:schemas`、`npm run typecheck`、`npm test`。这些只证明代码行为，不证明成片质量。
3. 用脚本`--help`或源码确认参数，再恢复本地模型配置。先检查旧进程是否仍活着；锁文件或旧PID本身不能证明任务在运行。
4. 修复图片生成和权重清单连接；完成鲁肃独立声线短句、带羽扇入堂首帧、约3秒双人动作验证。逐项通过后才扩展。
5. 修复“然”与其余配音问题，补齐10个角色33条对白；逐句试听、逐镜绑定音画，登记验收证据。
6. 完成全片场次覆盖：全景、双人、正反打、特写、反应、道具与空间关系；重点验证全身运动、羽扇遮挡、胡须和口型一致性。
7. 按导演稿剪辑、字幕、环境声和配乐，检查整片剧情和音画；通过后输出成片与验收报告。没有通过的镜头保持REVISE，不能把测试片标成完成。

一次只跑一个重型媒体或ASR任务。导演剪辑必须经`media_resource_guard.py`，FFmpeg RSS上限1024 MiB、最低磁盘2 GiB、超时30分钟、每0.5秒监控；解码编码线程2、滤镜线程1。先短样，再长任务；长字幕用单一字幕叠层。输出到partial文件，成功后替换，保留已接受媒体。RSS不是统一内存/GPU总占用，不得据此宣称不会OOM。不要为查看样片启动ComfyUI或完整服务栈，不自动重试昂贵失败任务。
