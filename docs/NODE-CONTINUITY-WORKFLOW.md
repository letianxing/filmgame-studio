# 节点连续性与减少返工

2026-11-06 用户要求：每个节点的场景、人物必须按剧情保持一致与连贯；在生成前消除可预见错误，减少积分返工。本流程适用于每个节点及其分支，不仅用于兵至。

## 1. 先确认剧情入口与出口

先做全幕预算约束，再做节点估算。节点估算是发现缺口的工具，不是逐节点追加额度的理由。余额快照须注明时间与来源；已扣费用不再次从新余额扣除，未结算/未扣的在途任务单独核对。全幕汇总全部分支的唯一待制资产、已采纳复用资产、公共战斗动作库、开场、UI展示、音频及返工储备；不能只按玩家单条路线估算，也不能将复杂节点成本乘节点数当正式预算。

全幕预测超额时，先调整镜头制作方案再新增付费任务：保留关键剧情与必要动作，复用符合人物、道具、空间、光照状态的已采纳动态素材；选择等待不按等待时长生成视频；分支只制作真正不同的表演，共用段只制作一次；战斗基础动作按角色/技能复用。不能以静帧冒充正式动态剧情、删掉分支因果或压缩对白来伪称预算达标。廉价模型只有实际报价和代表镜头质量验证后才能计入节省额。完整清单未核完时，只能给预算目标与缺口，不承诺余额足够交付全幕。

2026-11-06 本项目用户最新余额为9045积分。此前N03约2548积分是包含历史占用的复杂节点估算，不是每节点目标，也不应整笔再扣当前余额。当前未完成全幕唯一资产核算，不能承诺9045足够；在核算前不扩大后续付费批次，保留已提交任务并正常收片审核。此条为流程约束，尚不代表跨项目钱包硬门禁已实现。

制作前先按剧本、分镜与分支图估算整个节点的积分配额：列出剧情、选项回应、等待循环、战斗、概念图和音频的稳定assetId、计划秒数/张数、复用来源、模型及价格证据。共用后半段只计一次；已经采纳且可直接复用的素材不重复生成。用 `apps/orchestrator/src/node-quota.ts` 汇总已占用额度、待制基础费用与明确比例的返工预留。未知音频价格或未实测对白必须显式列为未定，不能按零费用宣称全节点报价完成。先形成节点预估，再设置执行配额与批次；实际每次提交仍以实时平台报价、人工审片和限额为准。不得把任意初始上限耗尽当成账户余额不足，也不为整节点预算获准而批量制作尚未定稿的依赖镜头。

读取当前剧本、状态机、上一个节点最后采纳镜头。记录本节点开始时的地点、时刻、在场人物、人物知道的信息、携带物、伤势与情绪；结束时记录同一组状态，并指向下一节点。

每次换地点回答：从哪里来、为什么移动、沿哪条路径、花了多久、谁跟随。需要过渡就明确对应镜头，不能让模型自行补空间。台词只能使用人物此时已知的信息，不能提前透露悬疑。剧情内选项进入对应回应片，只有完整节点结束才按项目规则回图。

## 2. 建立可复用的连续性记录

### 每次审片都转为下一次输入约束

每条人审意见记录「原话与版本SHA → 根因 → 可复用规则 → 本节点具体提示词 → 检查方法」。分清全局规律、角色设定和本镜动作，不能把某镜动作机械复制到所有人物。修订现有冲突句，不在同一提示词后追加相反要求。规则必须用于概念图和视频两个入口，并在新节点准备时复核；仅写交接不算落实。已采纳参考保留原SHA，但明确参考约束范围：定妆锁脸和衣甲，场景图锁空间，未获认可的兵器/群演细节不能随参考继承。

身份可读性是本轮新增通用门：同画面的不同身份不能只靠手里道具区分。逐类写清轮廓、衣料与防护覆盖、腰带和身份饰件、道具、站位、动作权力关系；身份饰件必须符合时代与人物经济地位，不能自动添加军衔章、华丽冠饰或把低阶领队装扮成将军。即便遮住兵器，观众仍应大致分清领队、执行者、平民；同类人物保持共同服制但不复制脸与体型。背景人物也逐组核对，尤其检查推镜后才露出的人。

本项目兵至映射：什长沿用已采纳成熟有须、宽肩体型与较完整皮甲，实用皮腰带，腰佩带鞘青铜剑，盘问时剑不出鞘，以空手手势指挥；九名普通士卒沿用独立采纳的简朴防护服制，持长柄青铜戈，横向短刃可辨，警戒封路。持农具的村民穿无甲粗麻布衣、布带或绳束腰，无军用肩甲/甲裙/成套束装，站在村民侧缘，不能混入军列像持农具的士兵。火把持有人另明确握持与交接，不能双手持戈同时凭空多出持火把的手。上述是本作美术设定，不宣称什长佩剑属于确定历史军制。

延续此前经验：角色年龄脸型、衣装层级、道具持手与交接相位、人数与背景人物身份、子场景几何、时间天气、世界主光及反打关系、地面接触与受力、视线/轴线和分支汇合状态均纳入每镜前检。按镜头相关性选择必要约束，别将整份规则重复堆进所有提示词。基础审查应在首/中/尾及新露出人物的帧核对，静帧采样不能冒充全片动作或口型审核；人审依然决定是否采纳。

第二次身份构图拒收追加经验：身份必须从头到脚一致，不能只改上衣却保留错误身份的裤装、束胫和鞋。每组人物明确所在区域、每只手握什么、道具归谁、是否接地；复杂群像避免相邻手臂和兵器重叠造成肢体归属歧义。衣装颜色逐部位继承采纳参考，不能自行增加亮蓝饰件。道具状态写成可见结构：入鞘剑只露柄，护手以下由闭合不透明剑鞘遮住，不能仅写“佩剑”；戈的横刃和柄顶结构分别描述。原场景参考含错误人物时显式隔离其约束范围，修订先用低成本构图核验，不带着结构错误直接生成视频。

每个对象使用稳定ID与版本；下面是生产记录要求，不代表全部已有专门UI字段。

| 对象 | 必须记录并核对 |
| --- | --- |
| 人物 | 已采纳参考的版本、SHA、审核决定、脸型、年龄、体型、服饰、发型、惯用手；双人图明确哪个人对应哪个角色 |
| 群体 | 领队与普通成员的身份差异、总人数、服制、站位；普通成员面容不复制领队或互相克隆 |
| 场景 | 已采纳场景来源及时间码、可识别地标、建筑材料、道路/水岸高差、出入口、相对方位、时间天气、主光方向 |
| 道具 | 所有人、所在手/腰/领内、外形与尺寸、交接顺序；接触先于受力，不凭空出现或重复交接 |
| 镜头 | 开始和结束的人物站位、视线、脚步支撑、持物、动作相位；景别、轴线、运动方向与叙事目的 |
| 声音 | 谁说话、对谁说、语气重音、实测时长、环境声延续、音乐进入/退出点；计划台词时码不能冒充实测 |

同一地点换机位不等于换场景。延续地点必须有独立场景视觉参考，不能只上传人物图后在文字中写“同一村庄”。人物参考里的背景只能作为辅助；必须明确哪张图约束环境、哪张图约束身份，避免互相污染。

### 大场景与子场景必须分开

每镜写明“大场景ID／子场景ID／具体机位”，例如桑丘村／老桑家门口与桑丘村／村口社树空地是两个地点。同属一村只约束建筑材料、地域、地貌和整体美术，不等于复制家门、院落、河岸与人物站位。家门口参考只能作为村庄风貌参考，不能标为已采纳村口构图。新子场景先审空间关键帧，记录道路如何连接旧地点、出入口、遮挡、距离层级；未确认的相对方位明确为待审设计，不伪称旧片已建立。

时间也独立核对：早晨的家门口与傍晚的村口可共用材质和地域，但不能机械复制晨光。节点间时间推进须有可读的转场，节点内则保持连续光向和天气。

每个子场景记录一份世界光照设定：时间、太阳所在方位与高度、天空/天气、环境补光以及可见火源；每镜另记录相机位置和朝向。先由世界光源推导画面内的受光面、投影方向和长短，再决定顺光/侧光/逆光；不能把“画左打光”复制给所有反打机位。人物与屋墙、树木、地面共享光源和接触阴影；火起后只在合理距离增加局部暖光，不让太阳跳位。关键帧审核检查亮面与阴影是否相互对应，视频审核另检查移动时是否漂移。方位属于美术设计锁定值，不冒充未计算的历史天文数据。

节点边界不是光照重置点。同一场景连续事件继承上一采纳镜头的太阳方位/高度、色温、曝光基准、天气和阴影软硬，不能为了单镜“电影感”突然改成浓重夕阳或冷蓝夜景。换机位只改变相对受光关系，不随机改变整体时段。若剧本确有时间流逝，先安排可读的时间过渡，再逐步调整光照；未有过渡不能仅靠节点名称宣布时间已变。审片必须并排对照前节点尾镜、本节点首镜及中间转场；单张空间构图获准不自动证明跨节点光影连续。

群演按身份、知情程度和性格安排，而非均匀围观：主持交涉者靠前；好奇者在安全距离旁听；担忧者退后护孩子；准备阻拦者持农具但在冲突升级前不主动挥击。记录每组位置、视线和情绪递进，给道路和主要人物行动留空间。儿童不能无因站到兵器前，主角与熟人不能只因参考图而复制成相同姿态。人数、恐惧和动作不能跨镜随机变化。

新地点先做低成本空间关键帧并经人工采纳，再生成视频。已有采纳地点优先复用原帧及必要的互补角度，不重新随机设计建筑。远近镜头共享地形与比例；看不到的区域不能凭空声明已验证。

## 3. 付费生成前的人工/agent检查点

1. 剧本、镜头描述、角色配置、状态机之间没有冲突。每镜scene只写实际出现地点，不复制整节点路线。
2. 人物与场景的实际参考均已绑定到本次生成请求，回读确认来源可用；提示词中的角色/环境名称对应明确的node或resource引用。仅在MD里写参考路径不算绑定。
3. 使用已采纳版本的SHA；没有角色和环境绑定、参考失效或版本不明时，不提交付费视频。
4. 检查上镜末态与本镜初态；衣物、道具、脚位、视线和轴线可衔接。分支汇合前各路径必须达到相容状态。若阿豆只有某分支到树后，公共镜头不得显示其他分支中未发生的移动；可用合理遮挡或必要的汇合动作解决。
5. 等待片只保留呼吸等微动作，不进行新交接、不替玩家选择；以可用短循环控制时长，不能把所有缺片默认12秒。
6. 读一遍对白，确认计划片长足够；需要拆镜时先拆计划与状态机，不用加速台词弥补。
7. 回读保存的模型、时长、画幅、提示词与参考集合，确认报价和项目剩余预算；持久化任务身份后只提交一次。

这些是执行门，不代表现有服务已经自动检测全部语义条件。当前系统有SHA/人工审核、预算和请求回读；完整空间、表演和剧情连续性仍由agent检查与人工审片共同验证。未通过检查不可写成“系统已保证”。

## 4. 小批制作和审片

先做覆盖主要人物、环境与动作风险的入口或关键镜头；通过后复用已采纳末帧/场景制作同场等待和分支，不能在首镜未定时批量做整条剧情。首镜必须与前节点原片并列对照，不能只看单片是否漂亮。

基础检查分两类：技术检查（解码、帧率、音轨、时长）与内容检查（地标、身份、军阶、人数、光向、接触、运动、台词和声音）。技术通过不能代替内容通过。记录真实看过的范围，抽帧不冒充全片原速审看；通知和人工采纳也必须分别记录。

## 5. 返工先定位差异，再花积分

记录“预期／实际／时间码／受影响对象／输入缺口”。保留已经通过的人物、台词和动作设计，只修改失败条件，但若供应商不能局部编辑，应明确需要整镜重生成及其费用，不声称能无损保留原表现。

场景不一致先查是否真正绑定场景、是否混用其他地点、是否缺少建立镜头；角色不一致查身份绑定和参考版本；动作错误查支撑、接触和动作复杂度。没有根因和新的输入改善，不原样重投。服务端失败或查询超时先查原任务，不换ID重提。

拒收媒体按用户清理规则删除，保留轻量SHA、根因、费用、删除回执；保护已采纳源及仍有依赖的资源。只有新版本经人工采纳后才交runtime，随后验证真实分支、转场、回图和存档。
