# 本地视频与表演方案：2026-10-14

本机：M4 Pro，48GiB统一内存。用户允许下载本机可用的开源方案，并在14B验证可替换后清理5B。视频主路线仍为Wan，不自动调用付费服务；片长不再强制30分钟。

## 为什么此前没有14B

此前选5B是保守测试选择，不能据此断言14B无法运行。官方Wan2.2 I2V-A14B示例要求至少80GB显存，描述的是该官方推理配置，不是所有量化/移植路线的理论门槛。[官方说明](https://github.com/Wan-Video/Wan2.2)

本机已安装的Blaizzy/mlx-video支持双模型14B，但默认同时加载高、低噪声专家。找到的Anes1032 q8两专家约30.8GB，尚不含激活、VAE等；超过当前24GiB进程安全档。[MLX实现](https://github.com/Blaizzy/mlx-video)、[q8模型](https://huggingface.co/Anes1032/Wan2.2-I2V-A14B-mlx-q8)

已完成下载及SHA256验证，正在实际推理。采用SceneWorks包内q4目录：两专家各约8.38GB，加对应VAE，选择性下载约17.27GB。固定修订c6c786170031eccc3a1fac0f98f1ad4ff988271e，逐文件SHA256校验；T5复用既有转换结果并移动到独立共享目录，5B退役不能删除它。该包README主要描述根目录BF16，q4以实际子目录config和张量头为准，不混淆两者。[模型包](https://huggingface.co/SceneWorks/wan2.2-i2v-a14b-mlx)

14B试验限制为512×288、最多17帧、量化4位、group64，原生16fps；MLX预算20GiB，RSS24GiB，系统可用内存至少8GiB，交换增长最多1GiB。首轮只是比较，不直接开放长片批量生成。新转换包严格检查模型参数，禁止静默忽略缺失权重。主VAE与5B VAE不同，不能复用错版本。

I2V-A14B是图生视频；S2V-14B才是音频驱动视频。换I2V模型不等于自动获得对白、口型或物理正确性。

## 辅助项目选择

| 方案 | 本片用途 | 本机证据和决定 |
|---|---|---|
| LivePortrait | 小幅表情、眼嘴运动与人物身份保持的试验 | 已独立安装，使用safetensors和MediaPipe，不使用InsightFace检测权重；完成49帧、表情幅度0.3、固定姿态的测试。约36.6秒，观察到进程峰值约1.04GiB；MPS不支持的grid_sampler_3d回退CPU。抽帧比早期MuseTalk下半脸重建更稳定，但未验收精准口型、侧脸和全场景合成。 |
| MuseTalk MLX | 已配音对白的口型 | 已安装并跑通，缩小嘴部掩膜可保留外围像素，但仍有嘴部质量问题；暂不批量应用。 |
| Blender | 案席、座次、路线、机位预演 | 本机5.2.1已实际生成独立场景与预览图。10名有唯一ID的代理人物与10案；检查孔明0.4m半径路线对案桌的二维采样间距。不是人物最终资产，不宣称已验证衣摆和跪坐。 |
| InfiniteTalk / MultiTalk | 音频驱动长对白、多人物对话 | 有实际开源实现，但现成安装使用CUDA/FlashAttention；本机尚未验证，暂不下载大包。模型长视频能力不等于一键完成历史群戏。 |
| Wan2.2 S2V-14B / Animate-14B | 音频或表演驱动 | 功能更贴近说话与动作，但尚无本项目可复现的Mac运行证据，与I2V-q4分开评估。 |
| VACE | 参考、掩膜、姿态/深度等控制 | 作为后续约束工具候选；不声称装上即可消除穿模，不在本轮同时下载。 |

来源：[LivePortrait](https://github.com/KlingAIResearch/LivePortrait)、[支持MediaPipe和Mac的社区接入](https://github.com/kijai/ComfyUI-LivePortraitKJ)、[MuseTalk MLX](https://github.com/xocialize/musetalk-mlx)、[InfiniteTalk](https://github.com/MeiGen-AI/InfiniteTalk)、[MultiTalk](https://github.com/MeiGen-AI/MultiTalk)、[VACE](https://github.com/ali-vilab/VACE)。

本地安装均通过配置、CLI或公开Python接口调用，未修改上游源文件。各运行环境独立，重型任务串行；下载与小文件文档工作可继续，不同时运行视频、ASR和表演模型。

## 退役5B的顺序

先完成14B完整权重校验，再运行同参考短片，检查是否在资源限制内成功以及是否改善身份和细节。通过后将默认模型、模型标识、原生帧率、缓存指纹和文档同步更新，再清理5B专用主模型与VAE。共享T5、角色图、原始样片、剧本和审查证据保留。若14B失败，不提前删除唯一已运行的回退路径，也不偷偷回退云端。
