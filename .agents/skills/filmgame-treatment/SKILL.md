# 影片开发梗概与提案

先读取已经确定的前提、人物、主要事件、结局、风格和时长。分清剧本已有内容与为了提案提出的补充，未知的信息留待定，不因提案需要完整就编造事实。

按实际用途组织片名、形式和目标观众、一句话故事、主要人物、完整故事梗概与表达意图。内部开发梗概通常交代结局；对外宣传简介是否隐藏结局遵循用户用途。篇幅按请求与影片体量确定，不硬套页数或五个角色上限。

故事梗概写出人物在转折处做了什么、代价是什么，并压缩连接段。主题说明必须能回到具体情节。该模块不替代逐场对白稿，也不自动做市场成功预测。

输出可供合作方阅读的文稿；在工程 JSON 中将其作为导出件记录，既有剧本与锁定事实仍为来源。

## 项目边界与来源

在 FilmGame Studio 中使用本模块，遵守仓库 AGENTS.md 和用户已明确的创作范围。持续项目遵循仓库根目录 `docs/SCREENWRITING_WORKFLOW.md` 的 JSON 校验、版本与导出契约；局部口头建议不强制建立项目。只有用户授权的制作请求才进入付费媒体阶段。

本文件是第一方项目适配，不是上游原文副本。方法来源：[固定版本的 treatment-writer](https://github.com/ur-grue/autopunk-media-skills/blob/39e119bfef25957223d6c44fccab0329e936d2f6/skills/screenwriting/development/treatment-writer/SKILL.md)。许可证和引用边界记录在仓库根目录 `third_party/screenwriting/`；未打包上游书籍、影视剧本引文或参考语料。
